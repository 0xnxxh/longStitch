# LongStitch：产品、算法与广告变现调研

调研日期：2026-09-09。当前交付为调研与首版建议，尚未实现应用、部署 Cloudflare 或申请广告账户。

## 结论与定位

建议做成免费、无需登录、浏览器本地处理的手机长截图拼接网站，优先部署到 Cloudflare Workers Static Assets；纯静态产物也可以部署 Pages。

核心承诺是：**选择同一页面的连续截图，自动消除重叠，保留真实内容，发现不确定接缝时允许校正，导出清晰长图。** 自动拼接不能退化成简单排列图片，也不能用生成模型重画文字。

用户已明确补充：手机截图包含上下常驻元素和右侧滚动条，不能为处理这些元素而粗暴裁掉滚动内容。因此，“匹配时忽略什么”与“导出时保留什么”必须分开实现。

## 首版功能建议

### 完整主路径

选择截图 → 检查顺序 → 自动分析重叠与遮挡 → 预览长图和接缝 → 必要时校正 → 保存图片。

| 功能 | 首版要求 |
| --- | --- |
| 输入 | PNG、JPEG、WebP；手机相册多选，桌面拖拽/粘贴；新增、移除、调序、反转。HEIC 暂不承诺，遇到时解释如何转 PNG/JPEG |
| 自动拼接 | 同一设备、同一缩放、连续纵向截图；检测相邻重叠、完全重复图、无重叠与歧义匹配 |
| 固定元素 | 处理顶部状态/导航栏、底部工具栏、悬浮地址栏和右侧滚动条；匹配遮罩与输出保留范围独立 |
| 预览 | 全图缩放和接缝局部放大；显示“已匹配 / 需调整 / 无重叠”，不用未经校准的成功概率误导用户 |
| 手动校正 | 调整某对截图的相对位移和接缝；半透明叠加参考；调整固定区范围；撤销/重置。用户主动选择后才能不去重直接拼接 |
| 导出 | 默认 PNG；JPEG 可选；显示尺寸；通过能力检测提供手机分享/保存；导出前基础实体色遮挡并将遮挡真正写入像素 |
| 大图处理 | 以像素与内存预算控制，超限解释并让用户选择缩小或分段导出，不静默降清晰度，不把失败包装成成功 |
| 隐私 | 图片不上传、不进入埋点、URL 或日志；清空后释放对象 URL 和内存。刷新不承诺恢复，不先做账户或云相册 |
| 站点内容 | 英文与简体中文入口、实际使用指南、常见失败说明、About / Contact / Privacy / Terms，为检索和广告审核提供真实内容 |

初始验收规模建议覆盖 2–10 张原始手机截图，然后依据 iOS / Android 真机内存表现决定公开上限。“10 张”是试验范围，不是已经确认的产品容量。

暂不纳入首版：录屏拼接、远程网页截图、横向全景、自动 OCR 摘要、AI 补图、自动乱序恢复、云存储、公开分享图库、会员订阅系统。它们不决定当前用户路径是否成立。

## 实现逻辑：匹配遮罩不等于裁图

### 1. 保留原图，另建低分辨率分析副本

文件按确定顺序导入，检查实际格式、尺寸、方向和像素总量。保留原图供最终导出，分析副本做灰度、梯度和多尺度比较。尺寸或缩放不兼容时提示用户处理，不静默拉伸图片。

### 2. 估计固定、滚动和遮挡区域

同时观察两类证据：同一屏幕位置上保持稳定的元素，以及在相邻截图间按共同纵向位移移动的内容。不能只按“没有变化”认定固定区，因为正文空白和重复列表也可能没有变化。

状态栏、导航栏、底栏、悬浮按钮以及滚动条作为**匹配遮罩**或降低权重的区域。遮罩可以覆盖右侧几像素，但这不改变输出宽度。对动态 Safari 工具栏、半透明浮层，检测结果要带不确定状态，并允许用户修改。

### 3. 估计相邻截图的真实滚动位移

先用低分辨率行特征找到候选位移，再用多个分散的内容块做模板匹配和一致性验证。搜索以纵向平移为主，只容忍小幅横向偏差，不默认进行全景图的透视变形。

只有候选分数、候选间差距、有效纹理面积、多个内容块支持度都足够时才自动接受。滚动条、相同图标、相同按钮、大片单色背景不能单独成为决定性证据。需要时再增加 OpenCV.js 的 ORB 验证，不必一开始引入整个全景拼接系统。

### 4. 以页面内容坐标建立覆盖关系

每张图记录它覆盖的内容区间、位置变换和遮挡区域。先对原始相邻图估计位移，再统一规划各图保留区间；不要反复把上一轮合成长图拿来匹配下一张，以免固定栏和误差不断累积。

输出时遵循：

- **完整宽度保留。** 检测时忽略右边缘，不等于输出时剪掉右边缘正文。
- **滚动内容保留一次。** 对齐后在重叠区域中选择差异小、避开文字和遮挡的接缝；只有有对应覆盖证据的重复内容才能移除。
- **固定栏默认首尾各一次。** 顶部可用首张、底部可用末张，但常驻栏检测必须可修正。用户选择去掉外层栏时才执行裁剪。
- **滚动条/浮层优先用真实覆盖修复。** 若其他截图含有同一页面位置且该位置未被遮挡，可从该图取像素；无需删掉整条右边缘或整段底部内容。
- **无法恢复时诚实保留或提示。** 某个像素如果在所有截图里都被不透明浮层遮住，就没有真实数据可恢复。半透明浮层下也不能保证反算出原始像素。提示保留原状、调整选图或补拍，不能生成、涂抹后宣称原样恢复。

首版先做可靠的固定栏识别、整宽接缝与可校正输出；对局部遮挡替换只接受有明确对齐覆盖的情况。无需为了隐藏每一种浮层，引入一个完整图像修复平台。

### 5. 清晰合成与失败处理

使用原始分辨率像素和整数位置合成，文字区域不做模糊融合。PNG 默认无损；JPEG 的质量损失要由用户选择。低置信度应定位到具体接缝并给出调整入口，不能自动删除内容或将直接堆叠标作“自动拼接成功”。

### 本地样本约束

当前 `samples/` 有 6 张 PNG，全部为 1179×2556。已查看首张和末张：深色网页、重复样式列表、状态栏、Safari 底部浮动地址栏/工具栏及右侧滚动条。首末图的底栏形态不同，固定像素裁切不可靠。没有将这些样本提供给外部竞品。

这组样本可以做第一组开发回归，但尚未标注逐对真实位移、接缝与遮挡覆盖，不能声称算法已经通过。

## Cloudflare 与浏览器技术选型

建议用 **Astro 静态页面 + React/TypeScript 编辑器岛 + 浏览器 Web Worker**。公开指南与双语内容直接生成 HTML，编辑器承担图片交互。若决定近期只做工具页，Vite + React 同样可行；不需要两套前端，也不需要为本地拼图加数据库。

图像算法先采用专用 TypeScript 灰度/梯度匹配；用同一组失败样本决定是否引入 OpenCV.js/WASM。计算放在浏览器 Web Worker，主线程保留顺畅的排序、取消、预览交互。OffscreenCanvas 只在支持时使用，不把它作为所有手机浏览器的前置要求。

“Web Worker”是用户浏览器里的后台线程，“Cloudflare Worker”是服务端运行时，两者不同。

部署首选 Workers Static Assets，理由是初期纯静态就够，未来如果确实需要少量服务端功能，可以沿用同一个 Cloudflare 产品；Pages 也满足首版，不存在必须迁移的理由。

已核验的官方平台事实：

- [Workers 静态资源请求免费且不限量，存储无额外费用](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)。调用 Worker 脚本的请求另按 Workers 计费；不要为了静态站给所有 URL 配置 `run_worker_first`。
- [Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)：服务端 isolate 内存 128MB；免费 Worker 动态请求有 10ms CPU 预算及每日请求上限。限制适用于服务端运行，不是浏览器的图片数量上限。
- Static Assets 单文件上限 25MiB。若引入 OpenCV/WASM，需要检查构建产物；用户本地选择的截图没有因此获得“25MiB 上传限制”。
- [Pages→Workers 官方迁移文档](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/)说明两者静态资产成本结构相近，Workers 功能覆盖更广。

浏览器内存才是主要工程风险。单张 1179×2556 RGBA 约 11.5MiB，6 张仅解码像素已约 69MiB，还未加分析副本、长画布和编码缓冲。应按对分析、释放不再使用的缓存、低分辨率预览，导出时再按需读取原图。Canvas 的最大边长/面积和总内存随浏览器与设备不同，不能把某个浏览器的 32767px 当成统一限制；要验证目标 iOS Safari、Android Chrome 的实际导出。

### 中国大陆访问

Cloudflare 普通套餐不等于中国大陆节点服务。[China Network](https://developers.cloudflare.com/china-network/get-started/)要求 Enterprise、额外订阅及相应 ICP 备案/许可等条件。免费 Pages/Workers 的大陆可用性和延迟需用实际域名、运营商与设备测试；本次未做大陆网络测量。

建议海外优先并提供中文，域名、字体、JS、WASM 尽量自托管在同站，避免依赖第三方 CDN。之后如果大陆流量足以支持投入，再评估地域部署与备案，不先做双区域复杂架构。

### 广告对产品结构的实际影响

Google [AdSense Program policies](https://support.google.com/adsense/answer/48182?hl=en)（本次页面标注更新 2026-08-04）禁止在以私人交流为主要内容的页面、非内容页等位置投放；[库存价值政策](https://support.google.com/publisherpolicies/answer/11112688?hl=en)禁止无发布者内容/低价值内容的屏幕及错误、退出等空内容页面。截图可能含聊天、邮件和订单，因此把预览区直接堆满广告存在实际审核风险。

建议首版从结构上分开：

- `/en/`、`/zh-cn/` 和实用指南：产品说明、原创教程、真实示例；获批后仅在允许位置加载广告。
- `/en/stitch/`、`/zh-cn/stitch/`：完整编辑文档，不加载广告和会话回放脚本；文件和截图内容留在这份文档内。
- 内容页进入编辑器采用真正页面导航，不只是 SPA 切换后保留已经执行的广告脚本。代码层必须验证编辑器没有加载相关脚本；仅隐藏广告容器不能证明脚本离开。
- 不在处理等待、错误、下载按钮周围制造广告误点；不把看广告设为普通导出的前提，不往用户导出图内加广告。
- 广告被拦截、未同意或无填充时，工具仍应可用。

这是根据当前页面用途与政策做出的产品设计建议，不是对网站审批结果的保证。增加几篇敷衍的 SEO 文案也不能保证获批；内容需要真正帮助截图、纠错、导出和隐私处理。

预留真实域名下的 `ads.txt`、发布者配置与单一广告开关即可，不先构建多联盟竞价抽象。[Google 指引](https://support.google.com/adsense/answer/12171612?hl=en)说 ads.txt 强烈推荐但并非强制；拿到真实 ID 后再配置，不提交假发布者 ID。

对 EEA、英国、瑞士用户投放个性化广告时，[Google 当前要求](https://support.google.com/adsense/answer/13554116?hl=en)使用认证并集成 IAB TCF 的 CMP。根据实际地区和广告配置接入，不能把简单 Cookie 横幅等同于满足所有要求。

变现验证先看真实可投放页面流量、地区、展示率和报告收入。工具使用次数不等于可变现 PV；纯客户端编辑器的多次拖拽、计算不能被算成新页面浏览。当前无流量数据，不提供承诺性 RPM 或月收入估算。

## 下一步开发顺序与验收

1. **算法验证**：给现有 6 张样本标注真实顺序、对应内容、固定区和遮挡；做浏览器相邻匹配及全宽导出，人工检查每条接缝。额外加入“右侧有有效文字”“滚动条覆盖边缘”“底栏收缩”“重复列表”“无重叠”“重复截图”测试。
2. **完整工具路径**：手机选图、顺序、接缝校正、预览、基础遮挡、保存。检验真实 iOS Safari / Android Chrome，导出图片可打开、文字未重复/丢失/模糊、取消与失败可恢复。
3. **部署与内容**：双语静态页、指南与隐私说明、Cloudflare 构建及预览环境；网络记录核验图片未上传。私有 `samples/` 和调研证据不应被自动打包成公共站点素材。
4. **广告上线**：确认运营者资料、域名与选定平台资格，提交真实网站审核，通过后接广告；复核编辑器没有广告脚本、允许页面的广告不挡操作、广告失败不影响工具。

每一步用实际输出验证后再进入下一步。现在调研完成，算法成功率、真机容量、Cloudflare 实际部署、大陆网络和广告获批均未验证。

## 检索与证据边界

公网发现使用 Ketch search，显式 `random=[brave,tavily,exa,firecrawl]`；Cloudflare 先通过 Ketch docs / Context7 解析库再读取官方文档；已知 URL 使用 Ketch scrape。GitHub 元数据与文件使用只读 GitHub fetch。

- 一次 Brave `rate limited (key 1 of 1)`，该次最终成功 backend 为 Tavily。
- Tailor 官网直接 scrape 超时；功能依据为官方 URL 的搜索索引。
- Apple App Store 直接抓取返回了中国区首页而非目标详情，已剔除该正文；Picsew 改用其官方产品文档，Tailor 保留官方搜索索引证据。
- Mediavine、Media.net 发布者页、Journey 首页、百度百青藤入口部分请求 EOF；Journey 帮助页 HTTP 403。没有据此推断平台不存在，亦没有将未读取的资格当作已确认。
- 百度百青藤浏览器访问 `ERR_CONNECTION_CLOSED`；当前网页准入仍待核实。
- Upliftorch 使用无隐私合成图片走正常导入、预览、下载。一次下载按钮不在视口导致点击失败，滚入视口后正常下载。它是本次唯一完成网页输入到导出的竞品，不代表原生或其他开源项目也已实测。
